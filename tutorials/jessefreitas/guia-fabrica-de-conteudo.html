Fábrica de Conteúdo com IA: tudo o que operamos e como replicar

Inventário completo da operação que produz e publica todo dia no Instagram, YouTube, LinkedIn e status do WhatsApp com agentes Claude, voz clonada, vídeo por código e um painel de aprovação na Cloudflare. Cada item diz para que serve, onde conseguir o acesso, que permissões pedir e onde ele mora no setup.

Perfis: pessoal (IA aplicada) e empresa (OmniForge, nicho farmácias de manipulação) Redes: Instagram, YouTube Shorts, LinkedIn, WhatsApp Status Versão: 20/10/2026
Material de aula. Nenhum token, senha, chave, ID de conta ou login real aparece aqui. As variáveis estão listadas só pelo nome. Para replicar, cada aluno gera as suas.

Visão geral

O que a máquina faz, em uma frase por etapa

Pesquisa

Todo dia de madrugada um agente varre notícias de IA (EUA, China, Índia, Brasil), mede outliers de concorrentes no Instagram via Apify e grava a pauta do dia.

Produção

Agentes Claude escrevem roteiro e legenda, geram narração com a voz clonada (ElevenLabs), imagens (FLUX), vídeo por código (Remotion e GSAP) e passam por QA automático.

Aprovação

Toda peça entra num painel web como "aguardando". Nada sai sem o clique de Aprovar do dono. Sem aprovação perto da hora, o painel avisa no WhatsApp.

Publicação

Um Cron na Cloudflare publica na hora marcada pela Graph API, manda o Reel ao YouTube Shorts, o post ao LinkedIn e o story ao status do WhatsApp.

Entrega do CTA

Quem comenta a palavra do CTA recebe um PDF por direct. Um agente de atendimento lê a lista de entregas no GitHub e responde sozinho.

Aprendizado

As métricas dos próprios posts e dos benchmarks voltam para o lote seguinte: ganchos que ganham viram regra em um arquivo de aprendizados.

Mapa da arquitetura

Da pesquisa ao post, com onde cada dado fica guardado

Três princípios seguram a arquitetura: agentes produzem, um único publicador publica; mídia sempre em URL pública (a Graph API não aceita upload direto de arquivo, ela baixa da URL); e todo segredo em um só arquivo de variáveis, nunca no chat, em commit ou em post.

Detalhe por plataforma

Instagram (Meta Graph API) publicação e leitura das duas contas
Pré-requisitos
Conta Instagram profissional (Business ou Criador) ligada a uma Página do Facebook. Um portfólio no Meta Business Suite ajuda a organizar várias contas.
Criar o app
  1. developers.facebook.com → Meus apps → Criar app → tipo Empresa.
  2. Adicione o produto Instagram (API com login do Facebook).
  3. Em Configurações básicas copie o ID e a chave secreta do app → META_APP_ID, META_APP_SECRET.
  4. Para uso próprio o app pode ficar em modo de desenvolvimento, com você como administrador. Revisão do app só é exigida para publicar em contas de terceiros.
Permissões
instagram_basic, instagram_content_publish, pages_show_list, pages_read_engagement, business_management; para métricas instagram_manage_insights; para ler e responder comentários instagram_manage_comments; para direct instagram_manage_messages.
Gerar tokens
  1. Graph API Explorer → escolha o app → marque as permissões → gere o token de usuário.
  2. Troque por um token de longa duração (60 dias): GET /oauth/access_token?grant_type=fb_exchange_token&client_id=…&client_secret=…&fb_exchange_token=… → META_USER_ACCESS_TOKEN.
  3. GET /me/accounts com esse token devolve cada Página com o seu token de página (derivado de um token longo, ele não expira) → META_PAGE_ID_<CONTA>, META_PAGE_TOKEN_<CONTA>.
  4. GET /{page-id}?fields=instagram_business_account → IG_BUSINESS_ID_<CONTA>.
Como publica
Duas chamadas. 1) POST /{ig-id}/media cria o contêiner com image_url (só JPEG), ou video_url + media_type=REELS, ou media_type=STORIES, ou CAROUSEL com filhos criados antes. 2) Espera status_code=FINISHED (vídeo leva minutos) e chama POST /{ig-id}/media_publish. Versão usada: v21.0.
O que a API não faz
Não agenda (agendamos nós, no Cron do painel); não põe enquete, figurinha nem música licenciada em story; não aceita arquivo local, só URL pública.
No nosso setup
Scripts posts/publish_ig.py (carrossel, imagem, story), publish_reel.py, publish_collab.py (collab); no painel, painel/src/graph.js. Para apagar um repetido: DELETE /{media-id} com o token da página.
YouTube (Data API v3) Shorts automáticos
Criar o projeto
  1. console.cloud.google.com → novo projeto.
  2. APIs e serviços → ative YouTube Data API v3 (e YouTube Analytics API se quiser métricas).
  3. Tela de consentimento OAuth: tipo Externo, adicione seu e-mail como usuário de teste.
  4. Credenciais → ID do cliente OAuth tipo App para computador → YT_CLIENT_ID, YT_CLIENT_SECRET.
  5. Rode o fluxo OAuth uma vez no seu computador (ou pelo OAuth Playground) com access_type=offline e guarde o refresh token → YT_REFRESH_TOKEN.
Escopos
youtube.upload para publicar; youtube, youtube.readonly, youtube.force-ssl para ler e editar; yt-analytics.readonly para métricas.
Como publica
Upload resumível de um MP4 9:16 com menos de 60 s. Título = 1ª linha da legenda + #Shorts; descrição = legenda. Feito pelo painel logo depois de o Reel sair no Instagram (campo "Também no YouTube").
Armadilhas
Com a tela de consentimento em "Teste", o refresh token expira em 7 dias: publique o app em "Produção" para uso contínuo. Projetos de API não auditados podem ter vídeos travados como privados; confira no Studio o primeiro envio. A cota diária padrão é de 10 mil unidades e cada upload custa caro, então não faça reenvios em laço.
No nosso setup
posts/publish_youtube.py (manual) e painel/src/youtube.js (automático). Só o perfil pessoal vai ao canal; Reels da empresa não.
LinkedIn perfil pessoal
Criar o app
  1. linkedin.com/developers/apps → Create app. O LinkedIn exige uma Página de empresa vinculada ao app, mesmo para postar no perfil pessoal; o admin da página aprova o vínculo.
  2. Aba Products: peça Share on LinkedIn e Sign In with LinkedIn using OpenID Connect (liberam na hora).
  3. Copie Client ID e Client Secret → LINKEDIN_CLIENT_ID, LINKEDIN_CLIENT_SECRET.
Token
Docs and tools → OAuth Token Tools → escopos openid, profile, w_member_social → login com o perfil pessoal → LINKEDIN_ACCESS_TOKEN (~60 dias). Se o app receber refresh token, guarde em LINKEDIN_REFRESH_TOKEN (~1 ano) e as datas em LINKEDIN_ACCESS_EXPIRES / LINKEDIN_REFRESH_EXPIRES. O ID do membro sai de GET /v2/userinfo → LINKEDIN_PERSON_URN.
Como publica
API REST de posts com o cabeçalho LinkedIn-Version (AAAAMM). Texto, imagem, vídeo e documento PDF (o "carrossel" do LinkedIn). Link vai no 1º comentário.
Limites
w_member_social só publica: não lê métricas nem comentários de terceiros.
No nosso setup
posts/publish_linkedin.py (renova o token sozinho) e painel/src/linkedin.js. Regras de tom em linkedin/ADAPTACAO.md; passo a passo em linkedin/COMO-CONECTAR.md. Teto de 1 post por dia.
WhatsApp via WAHA status, alertas e pauta
O que é
WAHA (WhatsApp HTTP API) é um servidor que você hospeda (Docker) e que conecta um número de WhatsApp lendo o QR code, expondo uma API REST. Não é a API oficial da Meta.
Montar
  1. Suba o contêiner devlikeapro/waha numa VPS (Docker / Docker Swarm), com chave de API definida.
  2. Crie uma sessão e leia o QR com o celular. Usamos o engine GOWS.
  3. Guarde WAHA_URL, WAHA_SESSION, WAHA_API_KEY (cabeçalho X-Api-Key).
Chamadas usadas
POST /api/{sessão}/status/image|video|text (status), POST /api/sendText (alertas no grupo), leitura de status@broadcast para conferir se o status já existe antes de reenviar.
Armadilhas
Atrás de Cloudflare, mande User-Agent ou recebe 403. Vídeo grande (≈50 MB) falha: comprima com ffmpeg (-crf 26 -maxrate 2500k) para menos de ~16 MB. Duas execuções no mesmo minuto duplicam status: confira o status@broadcast antes e depois. Número não oficial pode ser bloqueado se abusar de volume.
Alternativa oficial
WhatsApp Business Cloud API (Meta) para mensagens a clientes. Ela não publica status.
No nosso setup
posts/whatsapp/status_waha.py, avisar_sem_sim.py, pauta_whats.py; no painel o Worker manda o status depois de o item sair no Instagram.
Cloudflare R2 armazenamento de mídia
Criar
  1. dash.cloudflare.com → R2 → crie o bucket → R2_BUCKET.
  2. Em Settings do bucket ative o acesso público (subdomínio r2.dev ou domínio próprio) → R2_PUBLIC_URL.
  3. R2 → Manage API tokens → token com leitura e escrita no bucket → AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY; o endpoint S3 https://<account-id>.r2.cloudflarestorage.com → R2_ENDPOINT.
Uso
Upload com boto3 (API compatível com S3). Chave por conta e peça: <conta>/<AAAA-MM-DD-slug>/<arquivo>. Confira com curl -I que a URL responde 200 antes de publicar.
Por que R2
A Graph API baixa a mídia de uma URL pública; o R2 não cobra tráfego de saída. Os PDFs das entregas de CTA também ficam lá.
Cloudflare Workers + D1 o painel publicador
Peças
Um Worker com assets estáticos (o painel em HTML/JS sem build), API em /api/*, banco D1 (tabelas itens, publicados, eventos, config), binding do R2 e Cron Trigger a cada minuto. Worker e não Pages porque Pages não roda Cron.
Criar
  1. npm i -D wrangler e npx wrangler login.
  2. npx wrangler d1 create painel-publicador e cole o id no wrangler.toml; aplique schema.sql e as migrações.
  3. Ligue o bucket R2 como binding MIDIA.
  4. Grave cada segredo com npx wrangler secret put NOME (lista na seção 4).
  5. npx wrangler deploy. O painel fica em painel-publicador.<sua-conta>.workers.dev.
Travas de segurança
Duas chaves para publicar: variável PUBLICAR="1" no Worker e interruptor ligado no painel. Senha para o dono; token separado para os agentes, que criam e editam mas nunca aprovam.
No nosso setup
Código em painel/ no repositório; importação de filas com painel/importar_fila.py.
ElevenLabs voz clonada
Criar
elevenlabs.io → plano Starter ou acima (clonagem instantânea) → Voices → Add voice → Instant Voice Clone com 1 a 5 min de áudio limpo seu → Profile → API key → ELEVENLABS_API_KEY. Anote o id da voz.
Padrão "voz B"
Modelo eleven_v3, endpoint /with-timestamps, stability 0.5, similarity 0.85, style 0.6, speaker boost, speed 1.05. Narração inteira numa chamada só, com no máximo 3 tags de emoção ([animado] no gancho, [impressionado] no dado, [sério] na opinião).
Armadilhas
O eleven_v3 corta a última palavra: some uma cauda curta ("Valeu, e até a próxima.") e corte no último silêncio antes dela (ffmpeg silencedetect). Frase por frase e multilingual_v2 soam robóticos. Personagens e robôs usam outra voz, nunca a do dono.
No nosso setup
posts/radar-ia/_natural/ (build_natural.py, story_voz.py, voz_cauda.py) e posts/motion-gsap/audio/voz.py.
Hugging Face (FLUX) imagens geradas
Criar
huggingface.co → Settings → Access Tokens → token de leitura → HF_TOKEN.
Uso
gradio_client num Space FLUX (ex.: Client("mcp-tools/FLUX.1-Krea-dev", token=…), api_name="/infer"). Sem token a cota ZeroGPU estoura.
Regra
Foto real primeiro (foto do autor, quadro de vídeo real, print com dados fictícios); FLUX é complemento. Quando usar, a legenda leva "Imagens ilustrativas geradas com IA".
Apify benchmark e outliers
Criar
console.apify.com → Settings → Integrations → API token → APIFY_TOKEN. APIFY_TOKENS é uma lista separada por vírgula se você tiver mais de uma conta para rodízio.
Uso
Atores de scraping do Instagram leem os últimos posts e Reels de uma lista de perfis (posts/ciclo/perfis.txt). O script calcula a razão de outlier: views do post ÷ mediana dos outros posts do mesmo perfil. Acima de 3x vira candidato a formato.
Ritmo
Segunda, quarta e sexta, uma rodada (~US$ 0,40, ~130 Reels).
No nosso setup
posts/ciclo/outliers_apify.py, ciclo_diario.py, APRENDIZADOS.md, ganchos.csv.
Remotion, GSAP, Playwright e ffmpeg vídeo por código
Remotion
Framework React que renderiza vídeo. Nosso molde posts/remotion-varia recebe um roteiro.json e gera o Reel: cenas de vídeo real (Mixkit, grátis), foto, número, barras, lista, contraste, chat e frase; paletas escuro, marfim e vinho. gerar.py renderiza mudo, mixa voz + trilha + efeitos, normaliza em -14 LUFS e roda o QA. Licença: grátis para pessoa física e empresas pequenas; empresas maiores pagam (conferir remotion.dev/license).
GSAP + Playwright
Cena em HTML com timeline GSAP pausada e window.seek(t); o Playwright (Chromium headless) tira quadro a quadro e o ffmpeg monta o MP4. Serve também para carrossel em vídeo. Pasta posts/motion-gsap.
Carrossel e imagem
HTML 1080×1350 renderizado com Playwright para JPEG (a Graph API só aceita JPEG).
ffmpeg
Mixagem, ducking da trilha sob a voz, loudness, compressão para WhatsApp, extração de quadros. Instale via apt.
Doutrina de motion
Skill do projeto skills/motion-omniforge/SKILL.md: curvas com nome (sem spring), manchete por máscara, corte whip, efeitos sonoros automáticos nos cortes.
OmniTalk atendimento que entrega o CTA
Papel
Plataforma omnichannel com agentes de IA. A conta do Instagram está conectada como caixa de entrada: comentários e DMs chegam lá. Um agente lê a lista entregas/entregas.json do GitHub (palavra → link do PDF no R2 + texto do direct), responde em público "Te mandei no direct" e manda o link no privado.
Replicar
Qualquer plataforma de atendimento com Instagram conectado e agente com ferramenta HTTP serve. O que importa é o contrato: lista de palavras ativa, PDF com URL pública, link só no direct.
Telas para conteúdo
Gravadas no app real com login de demonstração e dados fictícios, nunca recortadas de conversa de cliente.
Claude Code os agentes
Estrutura
Projeto com chat do coordenador e uma thread por frente de trabalho (lote do dia, painel, LinkedIn, notícias, WhatsApp). Cada thread roda num contêiner na nuvem com o repositório clonado e a pasta compartilhada do projeto.
Ambiente
Acesso de rede "Completo" (ou liberar graph.facebook.com, api.linkedin.com, *.googleapis.com, *.r2.dev, api.elevenlabs.io, api.apify.com). A mudança só vale para sessões novas.
Rotinas
Gatilhos agendados no servidor (varredura de notícias de madrugada, lote do dia, conferência de correções de hora em hora). Sobrevivem ao reinício do contêiner.
Memória
Uma nota por assunto com regras e decisões do dono; todo Claude novo lê antes de trabalhar. Espelhada no repositório em memoria/.
Skills
Instruções reutilizáveis: motion, storytelling, LinkedIn em pt-BR. Referência que o dono manda para "aprender" vira skill, não post.
Fontes livres e ferramentas de apoio sem chave
Vídeo
Mixkit (catálogo em remotion-varia/catalogo.json, ids usados nos últimos 30 dias são recusados). Material suplementar CC BY de artigos científicos.
Fotos
API do Openverse (CC0 e CC BY com crédito). Unsplash, Pexels e Wikimedia bloqueiam IP de datacenter.
Radar de links
SearXNG rodando no contêiner (Google CSE, Bing News em inglês, Hacker News, YouTube, GitHub). Complementa a busca; não lê Instagram.
No computador
yt-dlp para baixar referências; Concat (editor com MCP) para montagem final de vídeo real. Downloads rodam no PC, não na nuvem.

Ferramentas que rodam local

Sem API paga: instaladas no contêiner da nuvem (onde os agentes trabalham) ou no computador do dono

Tudo aqui é gratuito e de código aberto. O contêiner do Claude Code é recriado com frequência, então o que não vem instalado precisa entrar no setup script do ambiente (ou ser reinstalado no começo da tarefa).

Pipeline: produção, aprovação, publicação

Estados de cada peça e quem age em cada etapa

  1. Pauta. A rotina de notícias grava o arquivo do dia com as melhores marcadas. Antes de virar pauta, cada tema passa pelos dois checadores de repetição.
  2. Roteiro. O agente escreve 3 ganchos (POV/humor, número/resultado, pergunta/contraste), escolhe um e registra os três em ganchos.csv. CTA sempre concreto: "comenta PALAVRA", com palavra nova.
  3. Produção. Reel pelo molde Remotion (30 a 45 s, voz B, -14 LUFS, QA aprovado); carrossel 1080×1350 em HTML; capa 1080×1920. Mídia sobe ao R2.
  4. Entrega do CTA. PDF sem dados pessoais do autor, no R2, cadastrado em entregas.json como inativo.
  5. Fila e painel. A peça entra na fila do dia e é importada no painel como aguardando.
  6. Aprovação. O dono clica Aprovar (ou "Aprovar o dia", ou "Pedir correção"). Ao aprovar, o painel guarda o etag de cada arquivo: se a mídia mudar depois, a peça pausa sozinha.
  7. Publicação. O Cron confere teto do dia, 60 min desde o último feed, md5 e legenda contra o que já saiu, e publica. Estados: publicado ou pausado / atrasado / pulado / erro.
  8. Desdobramentos. Reel vai ao YouTube Shorts; item marcado vai ao status do WhatsApp; post do LinkedIn sai no horário dele.
  9. Ativar a entrega. Depois de publicado, a palavra fica ativa em entregas.json e o agente de atendimento passa a responder.
  10. Medir. As views entram em resultados.py; padrão que se repete em 2 ou mais posts vira linha em APRENDIZADOS.md e muda o lote seguinte.

Regras e armadilhas aprendidas

Cada uma custou um erro real

Governança

  • Um único publicador por conta. Dois agentes publicando sem saber um do outro geraram 7 posts num dia. Agentes produzem; só o painel publica.
  • Nada sai sem o "sim" do dono, e o "sim" só vale no canal combinado (o clique no painel). O token dos agentes cria e edita, nunca aprova.
  • Hora chegou sem aprovação: avisar, nunca ficar em silêncio. Um dia inteiro ficou sem post porque o lote esperou um "sim" que o dono não viu.
  • Atrasado não sai em rajada. Passou 90 min: precisa de novo horário e novo Aprovar.
  • Anti-repetição é rotina. Tema repetido e story publicado duas vezes. Hoje: checagem de tema antes da pauta, md5 da mídia e legenda contra os últimos 24 posts antes de publicar. O "Publicar agora" em itens antigos duplicou posts porque eles não estavam no histórico.
  • Uma peça, um dono. Duas sessões refizeram a mesma peça e uma sobrescreveu a outra no R2.

Conteúdo

  • Nunca nomear concorrentes ou outros criadores; referência é só estudo. Fornecedores de IA podem ser citados.
  • Nunca prometer o que o produto ainda não faz.
  • Todo número com fonte; notícia confirmada em 2 fontes.
  • Dados de clientes só anonimizados e com autorização; nunca nomear o cliente.
  • Variar formato e gancho; nunca abrir todo Reel igual. Vídeo real e bastidor alcançam mais que notícia narrada sobre fundo animado.
  • Infográfico denso e rico; carrossel com foto real, mãozinha de "arrasta" na capa e CTA no último slide.
  • CTA que promete material precisa da entrega pronta antes de publicar.
  • Material que o dono manda para estudo é lido inteiro antes de usar.

Técnicas

  • Graph API: só JPEG em imagem, só URL pública, vídeo precisa esperar FINISHED.
  • Mudança de rede do ambiente só vale para sessões novas.
  • A voz eleven_v3 corta o fim: cauda + corte no silêncio. Trilha com ducking, nunca volume fixo.
  • WhatsApp: vídeo acima de ~16 MB falha; duas execuções no mesmo minuto duplicam.
  • Pasta de rede perde escrita em reinício: MP4 vai para o R2, não para a pasta.
  • Tokens: page token derivado de token longo não expira; LinkedIn ~60 dias (com refresh ~1 ano); YouTube em modo teste expira em 7 dias.

Replicar do zero

Roteiro para o aluno, na ordem em que as dependências aparecem

  1. Contas. Instagram profissional ligado a uma Página do Facebook; canal do YouTube; perfil no LinkedIn com uma Página de empresa; conta Cloudflare; conta GitHub.
  2. Repositório e arquivo de segredos. Crie um repositório privado com .gitignore incluindo config/meta.env. Copie o modelo da seção 4.
  3. R2. Bucket, acesso público, token S3. Teste: suba um JPEG com boto3 e abra a URL.
  4. Meta. App tipo Empresa, permissões, token longo, token de página e id da conta IG. Teste: GET /{ig-id}?fields=username.
  5. Primeiro post manual. Contêiner com a URL do R2 → media_publish. Se saiu, o caminho mais difícil está pronto.
  6. Voz. Clone a voz no ElevenLabs, gere 30 s com eleven_v3 numa chamada só, ouça o fim.
  7. Vídeo por código. Instale Node, ffmpeg e Playwright; renderize um Reel de teste com Remotion ou uma cena GSAP; mixe com a voz.
  8. Claude Code. Crie o projeto, conecte o GitHub, ambiente com rede completa e um setup que gera config/meta.env a partir das variáveis do ambiente. Escreva a memória inicial: público, tom, regras, o que nunca dizer.
  9. Regras de produção. Um REGRAS.md que todo agente lê: escopo (produz, não publica), checagem de repetição, formatos, CTA, QA.
  10. Painel. Worker + D1 + Cron, segredos gravados por você, PUBLICAR="0" até testar. Teste com um item, aprove, ligue as duas chaves.
  11. Outras redes. YouTube (OAuth + refresh token, app em produção) e LinkedIn (app com Página, token). Ligue no painel.
  12. WhatsApp. WAHA numa VPS para alertas e status. Sem isso, alertas por e-mail ou push já resolvem.
  13. Entrega de CTA. PDF no R2, lista palavra → link, agente de atendimento com Instagram conectado.
  14. Rotinas. Varredura de madrugada, lote do dia, conferência de correções. Comece com uma e aumente.
  15. Ciclo de aprendizado. Apify em 10 a 20 perfis de referência, razão de outlier, resultados dos próprios posts, arquivo de aprendizados lido pelo lote.
Ordem mínima para a primeira semana: passos 1 a 5 e 8 a 10. Com isso o aluno já produz com agentes e publica com aprovação. O resto melhora alcance e escala.
